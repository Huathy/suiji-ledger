## 1. 技术架构

```
                    ┌────────────────────────────────────────────┐
                    │              Docker Compose                 │
  浏览器/PWA ──────► │  Node 20 (NestJS)                           │
  (Vite 构建产物)    │  ├─ 静态资源服务 (Serve SPA)                 │
                    │  ├─ REST API /api/v1/*  (OpenAPI 自动文档)    │
                    │  ├─ 鉴权 JWT · 管理员口令                     │
                    │  ├─ 领域模块: bill/book/category/asset/       │
                    │  │   budget/tag/stats/import-export/backup   │
                    │  ├─ packages/qianji-compat (导入导出/格式)    │
                    │  └─ 定时任务: 自动备份 / 周期账单生成           │
                    │  数据卷: /data                                │
                    │  ├─ money.db (SQLite, WAL)                   │
                    │  ├─ uploads/ (账单图片)                       │
                    │  └─ backups/ (每日全量 JSON ×30)              │
                    └────────────────────────────────────────────┘
```

- **Monorepo（pnpm workspace）**：

```
suiji-ledger/
├── .docs/                     # 本文档集
├── apps/
│   ├── web/                   # Vue3 + TS + Vite + Pinia + Vant4 + ECharts
│   │   └── src/{views,components,stores,api,composables}
│   └── server/                # NestJS + Prisma
│       ├── prisma/schema.prisma
│       └── src/{auth,bills,books,categories,accounts,tags,budgets,
│                stats,import-export,backup,repeat,system}
├── packages/
│   ├── qianji-compat/         # 纯 TS 库：钱迹/微信/支付宝格式解析与生成
│   │   ├── src/{parsers,builders,types,mapping}
│   │   └── __fixtures__/      # 样本文件 + 快照测试（回归集）
│   └── shared/                # 前后端共享类型与常量（BillType 等枚举）
├── docker-compose.yml
└── README.md
```

- **关键工程约束**：
  - TypeScript `strict` 全仓开启；ESLint + Prettier 统一；
  - 兼容层 `qianji-compat` **零框架依赖**（可在 Node/浏览器双端跑），金额用 `bigint`/整数分运算，禁止 float 直算；
  - API 错误结构统一 `{ code, message, details? }`；列表接口游标分页（`cursor/limit`）；
  - 所有写接口幂等：导入类带 `idempotencyKey`。

## 2. 数据库 Schema 草案（Prisma 摘要）

```prisma
model Book     { id BigInt @id @default(autoincrement()) name String sort Int icon String? isDefault Boolean createTime BigInt updateTime BigInt bills Bill[] }
model Category { id BigInt @id bookId BigInt level Int parentId BigInt? name String icon String color String? type Int sort Int editable Boolean bills Bill[] }
model AssetAccount { id BigInt @id name String type Int stype Int? icon String color String? initMoney BigInt balance BigInt creditLimit BigInt? inCount Boolean @default(true) group String? sort Int status Int remark String? }
model Tag      { id BigInt @id bookId BigInt name String color String? sort Int }
model Bill {
  id BigInt @id @default(autoincrement())
  billId BigInt @unique            // 业务ID（导入时取钱迹 qj{id} 数字）
  bookId BigInt  type Int          // 0/1/2/3/20…，未知扩展 -2
  money BigInt                    // 分
  categoryId BigInt?
  assetId BigInt? fromId BigInt? targetId BigInt?
  assetName String? fromName String? targetName String?
  time BigInt remark String?
  fee BigInt? coupon BigInt?
  flags Int @default(0)           // bit0 nc / bit1 nb
  tagIds String?                  // JSON 数组
  images String?                  // JSON 数组
  source Int @default(0)          // 0/2/120/121/122
  importBatchId BigInt? refundOf BigInt? baoxiaoOf BigInt?
  rawPayload String?              // 导入未识别行的原文
  deletedAt BigInt?               // 软删除（回收站 30 天）
  createTime BigInt updateTime BigInt
  @@index([bookId, time]) @@index([categoryId]) @@index([assetId])
}
model Budget / RepeatTask / ImportBatch / User(口令) … // 字段对齐 SRS §4
```

## 6. 测试策略

1. **单元测试**（Vitest）：
   - `qianji-compat` 覆盖率 ≥95%：每个解析器对 fixture 逐字段断言；金额转换、类型映射、nc/nb、`#` 标签、`qj{id}` 解析专项用例；
   - 余额演算引擎：14 种 type × 账户角色矩阵；
   - 统计口径：nc/nb、退款冲减、优惠券不含入支出、转账不计收支。
2. **快照回归**：`__fixtures__/` 收录钱迹真实导出（CSV/XLSX/JSON 各一，脱敏）、微信/支付宝样本各一；解析输出 JSON 快照入库，格式变更立刻暴露（对应风险 R1/R2）。
3. **round-trip 测试**（核心）：导出 → 清库 → 再导入 → 逐字段比对（金额分、时间戳、类型、标签、标记、图片 URL）零差异。
4. **E2E**（Playwright）：登录、记一笔三类型、编辑删除恢复、月切换、筛选导出、导入向导全流程、深色切换等 12 场景。
5. **性能**：10 万行导入 <3min、月列表接口 P95 <200ms 的基准脚本纳入 CI（nightly）。
