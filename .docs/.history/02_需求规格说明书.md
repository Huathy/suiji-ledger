## 1. 引言

### 1.1 目的

定义 SuijiLedger（个人自托管记账系统）的功能需求、数据兼容性规格、非功能需求与验收标准，作为设计、开发、测试的基准。

### 1.2 产品定位

**"钱迹的个人自托管平替"**：

- 复刻钱迹的核心记账体验（记账/账本/资产/统计）；
- **数据兼容钱迹**：可导入钱迹导出的全部账单数据，可导出钱迹同构格式文件；
- 数据 100% 自有（自部署、单文件数据库、可随时备份迁移），无账号、无会员、无广告。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 账单（Bill） | 一笔收支/转账/退款等记录，含金额、类型、分类、账户、时间、备注等 |
| 账本（Book） | 账单的顶层容器（默认账本/旅行账本等），账单必属一个账本 |
| 分类（Category） | 二级结构（一级分类 + 二级分类），分支出/收入两套 |
| 资产账户（AssetAccount） | 现金/银行卡/信用卡/微信/支付宝/花呗等资金账户 |
| 债类账单 | 借入/借出/还款/收款/利息等应收应付记录（钱迹 type 4/6/7/9/10/11） |
| 钱迹格式 | 钱迹 App v4.5.3 导出的 CSV/XLSX/JSON 文件格式（见 §5） |
| 分（cent） | SuijiLedger 内部金额单位，1 元 = 100 分，整数存储 |

## 2. 总体描述

### 2.1 用户与场景

| 用户 | 场景 |
|---|---|
| 所有者（管理员） | 部署 SuijiLedger，设置访问口令；日常记账、查看统计、导入历史数据、定期备份 |
| 家庭成员（P1） | 通过同一实例各自记账（多用户隔离），或共享家庭账本 |

典型用户故事：

1. 我在钱迹记了 5 年账（导出得到 Excel），我要**无损迁入** SuijiLedger 继续记；
2. 我每月从微信/支付宝导出账单 CSV，**批量导入**并自动归类；
3. 我要随时**全量备份**，并在需要时把数据**导回钱迹可读的格式**（不被锁定）；
4. 手机上随手记账的体验要和钱迹一样顺手（3 秒记完一笔）。

### 2.2 系统边界

```
┌──────────────────────────── SuijiLedger ────────────────────────────┐
│  Web 前端（PWA，移动优先）          REST API（NestJS）                │
│  ┌──────────┬──────────┬─────┐    ┌──────────────────────────┐      │
│  │ 明细/图表 │ 记一笔    │资产 │ ←→ │ 账单/账本/分类/账户/预算…  │      │
│  └──────────┴──────────┴─────┘    └───────────┬──────────────┘      │
│       packages/qianji-compat（导入导出/格式转换）│                    │
│                                    ┌───────────▼──────────────┐    │
│  数据文件目录（SQLite + uploads）   │  SQLite (单文件)          │    │
└────────────────────────────────────┴───────────────────────────┴────┘
        ▲ 导入：钱迹 CSV/XLSX/JSON、微信/支付宝 CSV、SuijiLedger 备份 JSON
        ▼ 导出：钱迹同构 CSV/XLSX、SuijiLedger 全量备份 JSON
```

**明确不做**（Out of Scope）：账号注册/验证码/第三方登录、会员与支付、云端多设备实时同步（P1 仅提供备份导入导出）、无障碍自动记账、截图 OCR 记账、桌面小组件、广告与埋点上报。

### 2.3 约束

- 部署形态：Docker Compose 单容器，暴露一个 HTTP 端口；数据落在一个挂载卷（SQLite + uploads）；
- 浏览器兼容：近两年 Chrome/Safari/Edge 移动与桌面端；
- 时区：用户本地时区（默认 Asia/Shanghai），存储统一 UTC 毫秒时间戳；
- 语言：简体中文优先（i18n 预留）。

## 4. 数据字典（SuijiLedger 实体）

> 金额一律整数"分"；时间一律 Unix 毫秒（对外 DTO 可转秒/字符串）。字段命名对齐钱迹 JSON 命名（camelCase）以便映射。

### 4.1 Bill（账单）

| 字段 | 类型 | 说明 | 钱迹对应 |
|---|---|---|---|
| id | bigint PK | 本地自增 | `_id` |
| billId | bigint unique | 业务 ID（同步/去重/导出键） | `billid` |
| bookId | bigint FK→Book | 所属账本 | `bookid` |
| type | int | 见 §5.3 类型枚举 | `type` |
| money | bigint | 金额（分） | `money`（double 元） |
| categoryId | bigint? FK→Category | 分类（转账/还款类可为空） | `cateid` |
| assetId / fromId / targetId | bigint? FK→AssetAccount | 账户引用（语义见 §5.4） | `assetid/fromid/targetid` |
| assetName / fromName / targetName | text? | 账户名快照（导出需要） | `fromact/targetact/descinfo` |
| time | bigint | 账单发生时间（毫秒） | `time`（秒） |
| remark | text | 备注 ≤500 | `remark` |
| fee | bigint? | 手续费（分，>0）；优惠券存 negativeCoupon | `extra.transfee`（正/负） |
| coupon | bigint? | 优惠券抵扣（分，>0，独立字段避免歧义） | `extra.transfee<0` 取绝对值 |
| flags | int | bit1=不计收支(bit0) bit2=不计预算(bit1)（对应 nc/nb） | `extra.flag` |
| tagIds | bigint[] | 标签 | `extra.tags` |
| images | text[] | 图片路径/URL | `images` |
| source | int | 来源：0 手动 / 2 平台导入 / 120 周期 / 121 分期 / 122 自动 | `platform` |
| importBatchId | bigint? | 导入批次 | `packid`（近似） |
| refundOf / baoxiaoOf | bigint? | 关联原账单（退款/报销） | `extra.refundsid/bxsid` |
| status | int | 0 已删除 / 1 正常 | `status` |
| createTime / updateTime | bigint | 创建/更新时间 | `createtime/updatetime` |

### 4.2 其余实体（要点）

- **Book**：id, name, sort, icon, cover?, createTime, isDefault。
- **Category**：id, bookId, name, icon, color, level(1/2), parentId, type(0 支出/1 收入), sort, editable, builtin。
- **AssetAccount**：id, name, type(现金/储蓄卡/信用卡/虚拟/负债), stype(细分：微信/支付宝/花呗…), icon, color, initMoney, money(冗余余额), creditLimit?, group?, inCount, sort, status, remark。
- **Tag**：id, name, color, sort, bookId。
- **Budget**：id, bookId, scope(总/分类), categoryId?, type(月/年/区间), startDate, endDate, money, used(冗余)。
- **RepeatTask**：id, name, rule(日/周/月/年 + 参数), endDate?, nextRunTime, template(JSON 账单模板), status, generatedCount。
- **ImportBatch**：id, fileName, source(钱迹/微信/支付宝/备份), total/success/fail, time, errorReportPath。

实体关系：Book 1—N Bill；Category 1—N Bill（自引用二级）；AssetAccount 1—N Bill（三个外键角色）；Tag N—M Bill；Budget 1—N Category（可选）。

## 5. 数据兼容性规格（钱迹格式）

### 5.1 兼容口径总表

| 方向 | 格式 | 状态 |
|---|---|---|
| 导入 | 钱迹 CSV / XLSX（19 列） | P0 必须支持，含列头指纹识别 |
| 导入 | 钱迹 JSON（`key/date/.../sourceid`） | P0 |
| 导出 | CSV / XLSX，19 列与钱迹逐列一致 | P0（可作为"迁回钱迹生态"的数据源，第三方工具可读） |
| 导入 | 微信支付账单 CSV（GBK）、支付宝账单 CSV（GBK） | P0 |
| 双向 | SuijiLedger 全量备份 JSON（自有 schema v1） | P0 |

> 说明：钱迹 App 本身不支持从 Excel/CSV 导入（其导入仅接微信/支付宝/云闪付等平台账单，走服务端解析）。因此"导出兼容"的验收对象是**格式结构一致性**（可被 Excel/Numbers/数据库工具及脚本生态处理），而非"导回钱迹 App"。

### 5.2 钱迹导出文件格式（逆向确认，v4.5.3）

**CSV/XLSX 共 19 列**（源码 `Bill.getCsvTitle()`）：

| # | 列头 | 取值规则（源码 `toExportRow()`） |
|---|---|---|
| 1 | ID | `"qj" + billid`（导入时解析出数字作为 billId，保留前缀兼容） |
| 2 | 时间 | 本地格式化日期时间字符串（导入按 `yyyy-MM-dd HH:mm:ss` 优先，兼容多种常见格式自动探测） |
| 3 | 账本 | 账本名（导入时按名匹配/新建） |
| 4 | 分类 | 一级分类名（无分类填"其它"） |
| 5 | 二级分类 | 二级分类名，无则空 |
| 6 | 类型 | 中文：支出/收入/转账/还款/报销/退款/借入/借出/收款/利息支出/利息收入/已报销（对应 §5.3） |
| 7 | 金额 | 数值（元，double） |
| 8 | 币种 | 货币符号，如 `¥`（P0 仅支持 CNY，非 ¥ 行按原值导入并标注） |
| 9 | 账户1 | 支出/收入的账户名；转账=转出账户 |
| 10 | 账户2 | 转账=转入账户；债类=对手方账户 |
| 11 | 备注 | ≤500 字 |
| 12 | 已报销 | 报销账单且已报销金额>0 时为"是"，否则空 |
| 13 | 手续费 | transfee>0 时显示 |
| 14 | 优惠券 | transfee<0 时显示其绝对值 |
| 15 | 记账者 | username（P0 单用户忽略，保留字段） |
| 16 | 账单标记 | `nc`（不计收支）/ `nb`（不计预算）/ `nc&nb`，否则空 |
| 17 | 标签 | 多标签以 `#` 连接：`tag1#tag2` |
| 18 | 账单图片 | 图片 URL，多张换行分隔 |
| 19 | 关联账单 | 退款/报销关联的原账单 ID（`qj{id}` 格式） |

**JSON 行格式**（源码 `toExportJson()`）：`key`(qj+id), `date`, `category`, `type`(中文), `money`(数值元), `currency`, `asset`/`from`/`target`(**资产数字 ID**，需配合账户表映射；仅有账单文件时按未知账户处理), `remark`, `hasbx`(0/1), `fee`, `coupon`, `username`, `billflag`, `images`[], `sourceid`。

### 5.3 账单类型枚举映射表（钱迹 type ↔ SuijiLedger）

| type | 钱迹语义 | P0 处理 | P1 处理 |
|---|---|---|---|
| 0 | 支出 | 完整支持（含优惠券） | 同 |
| 1 | 收入 | 完整支持 | 同 |
| 2 | 转账 | 完整支持（两账户 + 手续费） | 同 |
| 3 | 信用卡还款（还款） | 完整支持 | 同 |
| 4 | 收款（债收入回款） | 导入保留，显示"收款"，只读 | 支持编辑 |
| 5 | 报销（待报销支出） | 导入保留，显示"报销" | 完整报销流 |
| 6 | 借入（债） | 导入保留 | 借还中心 |
| 7 | 借出（债） | 导入保留 | 借还中心 |
| 9 | 还款（债支出还款） | 导入保留 | 借还中心 |
| 10/11 | 利息支出/收入 | 导入保留 | 借还中心 |
| 20 | 退款 | 完整支持（关联原账单） | 完整退款流 |
| 21/22 | 已报销/报销包 | 导入保留（合并入报销语义） | 报销中心 |

**规则**：导入遇到任何未知 type/文案，账单**不丢弃**——落库 type=-2（扩展位）并保存原始行于 `rawPayload`，列表显示"其他"。

### 5.4 账户字段语义（余额计算规则，逆向确认）

- 支出(0)：`assetid` 账户余额 −money；收入(1)：+money；
- 转账(2)：`fromid` −money，`targetid` +money；手续费 fee 从 fromid 额外扣除；
- 信用卡还款(3)：`assetid` 为还款资金账户（−），`fromid` 为信用卡（+）；
- 借入(6)：`assetid` +money（进账），`targetid` 为债主（负债账户 +应付）；
- 借出(7)：`assetid` −money，`fromid` 为借款人（应收 +）；
- 收款(4)/还款(9)：对应冲减应收/应付；
- 退款(20)：`assetid` +money，且冲减原账单统计。

### 5.5 微信/支付宝账单 CSV 解析规格

- 编码：GBK（微信）/ GBK 或 UTF-8（支付宝，自动探测 BOM/转码成功率）；
- 微信（`微信支付账单(xxx).csv`）：跳过前 16 行表头说明，列：交易时间、交易类型、交易对方、商品、收/支、金额(元)、支付方式、当前状态、交易单号、商户单号、备注；`收/支`=收入/支出；"/"为转账（中性，默认记转账到"微信零钱"账户）；含"退款"状态行映射退款；
- 支付宝（`支付宝账单明细.csv`）：跳过前 24 行，列：交易时间、交易分类、交易对方、对方账号、商品说明、收/支、金额、收/付款方式、交易状态、交易订单号、商家订单号、备注；交易分类直接映射 SuijiLedger 分类（可建映射规则）；
- 分类映射：内置默认映射表（餐饮/交通/购物…），用户可在预览界面逐条调整并**保存映射规则**供下次自动应用；
- 去重：同"交易单号"优先；无单号则（时间 + 金额 ±1 分 + 对方名）指纹去重；已存在的行默认跳过并报告。

## 7. 验收标准（Release 判定）

1. **功能**：P0 需求全部实现并通过 E2E（记账→流水→统计→预算外的 P0 闭环）；
2. **兼容性回归集**（关键，固化于 `packages/qianji-compat/__fixtures__/`）：
   - 钱迹真实导出样本 CSV/XLSX/JSON 各 ≥1 份（人工导出），解析行数 = 文件行数，字段抽样 100% 断言；
   - 导出文件经"再导入"round-trip，金额/时间/分类/账户/标记/标签零丢失（图片 URL 字符串相等）；
   - 微信/支付宝样本 CSV 各 ≥1 份解析正确，去重生效；
   - 全量备份→清库→恢复→数据逐字段一致；
3. **数据正确性**：余额/净资产/统计汇总与手工对账一致（含手续费、优惠券、退款、nc 标记的边界用例）；
4. **非功能**：NFR 全项通过；Lighthouse PWA 基本可达。
