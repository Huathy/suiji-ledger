## 一、产品经理（PM）：产品重定位

**新定位：SuijiLedger = 月度平账记资产负债（Net Worth Tracker）**。用户唯一必做的动作是：**每月一次，把每个账户的实际余额抄进 App**（约 1 分钟）。其余全部由系统推导。

| 维度 | v1（逐笔记账） | v2（月度平账） |
|---|---|---|
| 核心动作 | 每笔记一笔（3 秒/笔） | **每月记一次各账户余额**（1 分钟/月） |
| 记什么 | 账单明细（餐饮/购物/交通…20+ 分类） | **只有账户余额快照**，无明细 |
| 类型体系 | 二级分类库 + 支出/收入 | **默认仅一个类型「平账」**；用户可自定义类型（工资/房贷/投资…），无层级、无预置库 |
| 首页 | 月度流水列表 | **净资产总览 + 月度走势 + 平账提醒** |
| 核心数字 | 本月支出/收入 | **净资产、月度结余（本月净资产 − 上月）** |

PM 强调三条产品原则：

1. **懒到底**：不逼用户解释每一分钱。想解释的月份，可以顺手给变动标类型/记几笔大项；不想解释，全部默认"平账"，数据照样完整。
2. **平账是兜底不是错误**：差额（余额变化中未被大项解释的部分）自动生成一条灰色的「平账」条目，语义是"这部分我不想知道细节"。它让账永远平衡，而不是报错。
3. **类型是标签不是枷锁**：自定义类型仅用于月报归因（"本月 +4,645：工资 +12,000 / 投资 +2,000 / 平账 −9,355"），不参与任何强校验。

## 二、系统分析师（SA）：数据模型 v2

原 Bill/Category 两张核心表退役，新模型仅 4 个实体：

```
Account 账户        id, name, icon(emoji), kind(资产|负债), group?, inNetWorth,
                    initBalance(分), sort, archived
MonthlySnapshot 快照 id, yearMonth("2026-10"), accountId, balance(分), note?
                    唯一键 (yearMonth, accountId) —— 平账页一次写一批
ChangeEntry 变动条目 id, yearMonth, accountId?, typeId, amount(分,±), note?, auto(bool)
                    月度恒等式：Σ(条目.amount) = Σ(账户.本月余额 − 上月余额)
RecordType 类型      id, name, emoji, color, builtin(「平账」内置不可删), usageCount
```

**平账算法（核心规则）**：

1. 用户保存某月快照后，系统算出每个账户的月度变动 `Δa = 本月余额 − 上月余额`；
2. 用户手动记的"大项"条目（工资、房贷等，类型自选）合计为 `S`；
3. 系统自动生成兜底条目：`平账 = Δ − S`（金额不可编辑，备注可改；`auto=true`）；用户不记大项时，平账 = Δ；
4. 事后修改快照余额 → 当月条目与统计全部自动重算（幂等）。

**派生指标**：净资产 = Σ资产余额 − Σ负债余额；月度结余 = 净资产月差；年度结余 = 年末 − 年初。

**边界约定**：新账户中途加入，首月无上月余额则 Δ=0；负债账户余额记"欠款正数"；回收站/软删除、时间毫秒、金额分等 v1 约定沿用。

## 三、架构师（Arch）：架构与兼容性

- 技术栈不变（Vue3/Vant4 + NestJS/Prisma/SQLite + Docker），模块由 `bills/categories` 改为 `accounts/snapshots/entries/types`，工作量显著缩小（明细流水、分类库、记一笔键盘的复杂校验全部消失）。
- **钱迹兼容保留且升级为亮点**：`qianji-compat` 新增**聚合器**——导入钱迹账单后，按账户重放每月累计收支，**自动生成历史 MonthlySnapshot**，让净资产曲线一步补全数年历史（v1 逐笔数据也不浪费）。
- 导出：月度快照表 CSV（月份 × 账户矩阵，Excel 友好）+ 自有 JSON 全量备份，保留 v1 的 19 列钱迹格式导出作为可选（供迁回钱迹生态）。

## 四、前端/后端意见

- **FE**：信息架构改为五 Tab——总览 / 走势 / ➕平账 / 账户 / 我的。平账页是全系统唯一录入界面：逐账户"上月余额 + 输入框 + 数字键盘"，实时显示变动合计；保存后即完成。空态引导三步：添加账户 → 填初始余额 → 设定每月平账提醒日。
- **BE**：快照批量写事务 + 重算幂等；`(yearMonth, accountId)` 唯一约束天然防重复平账；提醒用浏览器通知（PWA），无推送服务依赖。
- **测试**：平账恒等式（含多账户/中途加账户/改历史快照/负债方向）为最高优先级单测；钱迹聚合器以真实导出文件做快照回归。

## 五、决议

1. 通过 v2 定位与数据模型（§一/§二）；v1 文档中与之冲突的部分作废，钱迹兼容/非功能需求/Design Tokens 沿用；
2. 里程碑重排（约 32 人日）：**M1** 账户+平账+总览（可用）→ **M2** 走势统计+类型管理 → **M3** 钱迹导入聚合+导出/备份 → **M4** PWA 提醒+深色+发布；
3. FE 本周产出《06_UI设计稿_v2》与视觉稿（下次交付）；
4. 「平账」类型图标定为 ⚖️，自动兜底条目视觉上用中性灰弱化，与自定义类型区分。
