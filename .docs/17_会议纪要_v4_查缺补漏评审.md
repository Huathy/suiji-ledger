## 一、按用户旅程走查（PM 主导）

懒人用户的一个完整周期是：**月初想起 → 打开 App → 抄余额 → 平时偶尔调整 → 看走势 → 年底有完整曲线**。逐环节走查结果：

| 环节 | 现状 | 缺口 |
|---|---|---|
| 想起该平账了 | settings 存了 reminderDay，总览有黄条（打开 App 才可见） | **没有任何主动提醒**：PWA 通知、Electron 通知都没接。懒人最容易死在这一步 |
| 抄余额 | 平账页 + 键盘 + 大项 + （批量记录）✓ | 大项类型少时够用；**没有"和上月相同"快捷填充**（工资不变的月份，多数账户余额其实变了，此项价值低，不做） |
| 平时调整 | 单账户改余额 ✓ 单独平账记录 ✓ | 误删无解：**删除大项/借还/账户全是硬删**，没有撤销或回收站 |
| 看走势 | 净资产折线/结余柱状/区间日均/日均柱状 ✓ | **资产配置环形图没做**（06 号设计稿有）；**类型累计贡献**没做 |
| 数据安全 | 只有手动导出 JSON；服务端模式靠 data 目录 | **自动备份未落地**（v1 FR-1202 承诺过）：手机丢/重装 = 全没。这是全产品最大的风险敞口 |
| 借还 | 台账+进度 ✓ | **没关联资金账户**（借出的钱放在哪/从哪还）；**到期不提醒**（dueDate 存了没用）；已结清记录与在途混排 |
| 迁入迁出 | 钱迹导入 ✓ CSV 导出 ✓ | 导出无 **xlsx**（钱迹用户习惯 Excel）；无跨月**搜索** |

## 二、数据与技术缺口（SA / Arch / BE）

| # | 缺口 | 影响 | 建议优先级 |
|---|---|---|---|
| T1 | **自动备份轮转**：每次平账/调余额后自动落 `data/backups/backup-YYYYMMDD-HHmm.json`，保留 30 份；Electron/服务端同逻辑，安卓在应用目录 | 防呆兜底，配合导出让数据风险趋近于零 | **P0** |
| T2 | **平账提醒**：Electron 主进程用 Notification（每月 reminderDay 当天启动时检查）；PWA 用 Notification API + SW；总览黄条已有 | 懒人闭环的关键一环 | **P0** |
| T3 | **删除保护（最小化）**：删除大项/借还/条目后 toast 提供「撤销」（前端保留 5 秒可回滚，后端接口不动）；账户删除本就有快照保护 | 误操作兜底 | **P0** |
| T4 | **核心单测（Vitest）**：恒等式、区间日均、钱迹聚合器、set-balance——目前全靠手工回归 | 防回归，尤其聚合器（钱迹导入）改动风险最高 | **P1** |
| T5 | **借还 v2**：关联资金账户（accountId 可选）、dueDate 到期提醒（总览卡提示"3 笔借款 7 天内到期"）、已结清默认折叠 | 借还是用户点名功能，值得做完整 | **P1** |
| T6 | **xlsx 导出**：用已引入的 SheetJS 写总表 xlsx（CSV 保留） | 迁回钱迹生态/Excel 习惯 | P1 |
| T7 | **搜索**：跨月按备注/账户/类型/金额区间查快照与大项 | 数据多了以后找记录 | P1 |
| T8 | **资产配置环形图 + 类型累计贡献**（走势页补齐 06 稿设计） | 看钱都在哪 | P1 |
| T9 | 账户排序 UI（上移/下移）+ 分组重命名（批量改账户 group） | 整理体验 | P2 |
| T10 | 月度详情内直接新增大项（现在要跳平账页） | 少一次跳转 | P2 |
| T11 | 月报分享图（Canvas 生成某月净资产+构成） | 分享给自己/家人 | P2 |
| T12 | WebDAV 备份推送（坚果云）作为 Git 同步的替代评估 | 异地保险 | P2 |

## 三、明确不做（复议后维持）

- **多币种**：单币种定位（要记外币资产，建独立账户+手动折算即可）
- **自动记账/OCR**：与月度平账模型无关，且涉及高敏权限
- **多用户/云同步**：单人自用；备份文件即迁移手段
- **周期记账/分期**：月度快照模型下"工资到账"体现为余额变化，无必要
