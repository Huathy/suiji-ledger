# 实现记录 · 数据排序支持时间倒序/顺序（v0.3.8）

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-02 |
| 需求 | 「优化一下数据排序要支持时间倒叙/顺序」 |
| 产物 | 服务端 + Web/PC + 离线本地后端（APK）同一口径；`npm test` 42/42，`npm run build:web` 通过，服务端接口实测通过 |

## 一、设计取舍

1. **一个全站开关，而不是每页各存一份**
   新增设置键 `timeSortDir`（`desc` = 倒序，新的在前，默认，保持历史行为；`asc` = 顺序，旧的在前）。
   存 settings（服务端 SQLite / 离线 `db.settings`），本机同时存 `localStorage` 立即生效 → 换设备/重装跟随账号。
2. **默认值刻意不写进 `DEFAULT_SETTINGS`**
   缺键＝「用户还没设置过」，前端据此把本机值推上去；若给出默认 `desc`，新设备登录会被服务端覆盖掉刚调好的 `asc`。
3. **图表/趋势不受影响**
   净资产折线、日均开销柱状、区间分析、`/stats/*` 恒为时间序列（旧→新），翻转它等于把走势画反。
   只有「列表/表格」类数据跟随开关。
4. **`limit` 语义恒定**
   `/months?limit=N` 永远取「最近 N 个月」，`dir` 只翻返回的排列方向 —— 否则切到顺序就只看得到最老的 N 个月。
5. **两处钉死 `dir=desc` 的取数（改错会算错账）**
   - `HomeView`：本月卡片/迷你走势/上次记录日 依赖 `months[0] = 最近月`，只有「近几月」卡片显示顺序跟着翻。
   - `ReconcileView`：区间基线 `lastPointDate = pts[idx+1]` 依赖「近的在前」。

## 二、改动清单

### 共享层 `packages/shared/src/index.ts`
- `TimeSortDir` / `parseTimeSortDir`（只认 `asc`，其余回退 `desc`）/ `flipTimeSortDir`
- `sortByTime(list, timeOf, dir, tieOf?)`：字符串键按码位比较（字典序 == 时间序，不受 locale 影响），数值键按数值比；同时间键用 `tieOf`（自增 id）作二次键，与后端 `orderBy: [{ym:'desc'},{id:'desc'}]` 同口径；不改入参
- `TIME_SORT_DIR_KEY = 'timeSortDir'`

### 服务端（NestJS + Prisma）
| 接口 | 变化 |
|---|---|
| `GET /months?limit&dir` | 返回顺序可翻转，limit 仍取最近 N 月 |
| `GET /search?q&minYuan&maxYuan&dir` | Prisma `orderBy [{ym:dir},{id:dir}]` |
| `GET /loans?dir` | 改为**按发生日期 `date` + id** 排（原先只按 id，日期是乱的） |
| `GET /recycle?dir` | 按 `deletedAt` + id 排 |
| `GET /system/matrix.csv?dir` | 导出行序跟随方向，表头与列口径不变 |

### 离线本地后端 `apps/web/src/local/backend.ts`
同一套 `dir` 参数与 `sortByTime`，逐条对齐上述五个接口（APK 与服务端行为一致）。

### 前端
- `stores/ui.ts`：`timeSort` + `setTimeSort` / `toggleTimeSort` / `pullTimeSort`（登录后与服务端对齐一次，只拉一次）
- `App.vue`：非 `/login` 且已登录时 `pullTimeSort()`
- 开关入口（三处等价，任一处切换全站生效）：
  - **我的 → 外观与提醒 → 时间排序**（倒序/顺序 单选）
  - **PC 资产负债总表** 标题右侧「时间 ↓ 倒序 / ↑ 顺序」胶囊，且点「月份」列头可在倒序/顺序间来回切并同步全局
  - 各列表页头部胶囊：账户历史余额、搜索结果条、借还台账条、回收站条、月度详情「本月变动构成」
- 受影响列表：资产负债总表、账户历史余额、搜索结果（月份分组 + 组内条目）、借还台账（借出/借入 × 未结/已结）、回收站、月度详情变动构成 + **月报分享图前 8 条**、总览近几月卡片、走势页区间月份选择器、CSV/xlsx 导出
- 关键正确性细节：`AccountDetailView` 的 `delta` 恒按**时间顺序**递推（上月→本月），只有展示顺序被翻转 → 切方向不会把变动额算反

接口实测（一次性脚本 `verify-timesort-iso.ps1`，全部在三处隔离环境下跑）：

- `/system/matrix` 月份行恒为**时间升序**（`2026-06,2026-07,2026-08`），账户列余额按 `100000,150000,120000` 与写入序列一致 → 前端只在渲染层翻转，不改变数据本身
- 月度详情 `entries[i]` 字段含 `ym`（`sortByTime` 的 `timeOf` 依赖它，缺则会退化成纯 id 排序）
- `/search`：`asc` 得 `2026-06:六月A 2026-06:六月B 2026-08:八月C`，`desc` 为其完全逆序（同月内 id 稳定）
- `/loans`：`asc` 按发生日期 `2026-01-05 → 2026-09-05`，`desc` 反向
- `/recycle`：`asc` 为「先删的在前」，`desc` 反向
- `matrix.csv`：行序随 `dir` 互为逆序，**表头两向完全一致**
- `PUT /system/settings {timeSortDir:'asc'}` → `GET` 读回 `asc`
