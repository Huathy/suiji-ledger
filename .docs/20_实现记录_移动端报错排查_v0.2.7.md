# 实现记录 · 移动端「点开报错」排查与修复 v0.2.7

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-26 |
| 产物 | 安卓 `dist/SuijiLedger-v0.2.7.apk`（versionCode 9）· 前端 `apps/web/dist-mobile` |
| 现象 | 真机（MEIZU 20 / Android 16）打开账户、借还、回收站等页面，底部弹出红色错误提示 `Cannot read properties of undefined (reading 'slice')`，部分页面数据不显示 |
| 结论 | 不是网络/服务端问题，是**旧版本地库结构缺字段**导致本地后端抛异常 |

## 一、根因

真机 localStorage 里的 `mr_local_db_v1` 是旧版（v0.2.x）写入的，只有：

```
version / seq / accounts / types / snapshots / entries / settings
```

而 v0.5 之后新增了 `loans`（借还台账）与 `trash`（回收站）。`local/backend.ts` 的 `load()` 只校验了 `version === 1` 和 `types` 里有内置类型，就原样返回旧库，于是：

- `GET /loans` → `db.loans.slice()` → TypeError
- `GET /recycle` → `db.trash.slice()` → TypeError
- 账户页因为同时请求 `/loans`（虽然 `.catch()` 兜底），`api()` 会先弹 `showFailToast`，所以**每进一次账户页就弹一次红条**

CDP 实测（v0.2.6）：`/accounts`、`/loans`、`/recycle` 三页均触发该 toast，`/loans`、`/recycle` 同时有 console 异常。

## 二、修复

### 1. 本地库迁移（直接修复，`apps/web/src/local/backend.ts`）

新增 `normalize(raw)`：

- 缺失/非数组的 `accounts / types / snapshots / entries / loans / trash` 一律补成 `[]`
- `settings` 非对象时重置为 `{}`
- 账户补齐 `group / sort / inNetWorth / archived / note` 默认值；借还补齐 `settledAmount / dueDate / accountId`
- 缺内置「平账」类型时补一条
- `seq` 保证大于所有已用 id，避免主键冲突

`load()` 改为「解析 → normalize → 结构有变化才回写」，不再因为字段缺失就整库重置（旧逻辑会静默丢数据）。

### 2. 安卓壳加固（`mobile/src/com/suiji-ledger/app/`）

| 问题 | 修复 |
|---|---|
| `AssetHost` 在子线程里 bind，WebView 可能先发请求 → `ERR_CONNECTION_REFUSED` 报错页 | 端口绑定移到构造函数同步完成，失败只记日志 |
| 缺失的 `.js/.css` 被 SPA 回退成 `index.html`，浏览器按脚本解析报 `Unexpected token '<'` | 仅「无扩展名路径」回退，其余返回 404 |
| WebView 主文档加载失败直接显示 Chromium 报错页 | `onReceivedError` 对主文档做 8 次短重试（200ms 起递增） |
| `pickFile` 回调注入写法 `(window.cb||function(){}(x))` 因优先级永远不执行回调 → 「从备份恢复」选了文件没反应 | 改为 `((window.cb||function{})(x), null)` |
| 真机排查无日志 | 打开 `setWebContentsDebuggingEnabled` + `onConsoleMessage` 转发到 logcat（`SuijiLedger` tag） |

### 3. Android 15+ 边到边遮挡（`apps/web/src/styles.css`）

targetSdk 35 在 Android 15/16 上强制 edge-to-edge，页面标题被状态栏压住。`.app-main` 增加 `padding-top: env(safe-area-inset-top)`（真机实测 42px），底部原本已有 `safe-area-inset-bottom`。
